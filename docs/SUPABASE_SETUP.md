# Build 4 — Supabase Setup

The application code and SQL migration are prepared so the only remaining managed-backend step is account/project ownership and secret provisioning.

## What the migration creates

`supabase/migrations/0001_lead_ingestion.sql` creates:

- a private `leads` table;
- `BH-000001` style lead-number generation;
- server-only access (RLS enabled; no anonymous/authenticated table policies);
- a private `lead-photos` Storage bucket;
- an 8 MB per-file limit;
- JPG, PNG, and WebP MIME restrictions;
- indexes used by later scoring/outcome workflows.

## Human setup steps

1. Sign in to Supabase and create a project for Blue Horizon Pools / Romano Leads.
2. Open **SQL Editor** in that project.
3. Copy the complete contents of `supabase/migrations/0001_lead_ingestion.sql` and run it once.
4. In Supabase project settings, locate:
   - the project URL;
   - the server-side **service role** key.
5. Keep the service-role key private. Never paste it into a source file, issue, commit, screenshot, or public chat.
6. For local testing, create a `.env` file from `.env.example` and set:

```text
SUPABASE_URL=<project URL>
SUPABASE_SERVICE_ROLE_KEY=<server-only service role key>
SUPABASE_STORAGE_BUCKET=lead-photos
```

7. Run the opt-in integration test locally:

```bash
npm install
npm test
```

When both Supabase environment variables exist, `tests/supabase.integration.test.mjs` runs automatically. Without them it is safely skipped.

## Production secret placement

The same environment-variable names must later be configured in the production hosting environment. The values must not be committed to GitHub.

## Verification expected after setup

A successful configured test proves that:

- `next_lead_number()` returns a `BH-######` identifier;
- the private photo bucket rejects disallowed MIME types;
- an allowed image can be stored;
- a test lead can be persisted and read back;
- the test record and photo can be cleaned up afterward.

After that, perform one browser form submission against the running Astro server and verify the lead and photo paths appear in Supabase before Build 4 is certified complete.

## Security notes

- The browser never receives the Supabase service-role key.
- Public form submissions go only to `/api/leads`.
- Server-side validation repeats all important browser validation.
- Storage paths are generated by the server; user filenames are not trusted as paths.
- The Storage bucket remains private.
- Anonymous database access is intentionally not enabled.
